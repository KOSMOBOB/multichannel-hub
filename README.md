# Multichannel Hub — Омниканальный шлюз

Омниканальный шлюз (агрегатор каналов связи) для приёма обращений из разных источников
(Telegram, WhatsApp, веб-формы и др.) в единую систему с пересылкой во внешние CRM и сервисы автоматизации
(Bitrix24, n8n, Make, Zapier) через вебхуки.

Архитектура модульная — новые каналы (VK, MAX, Instagram и т.д.) добавляются без
переписывания ядра.

## Возможности

- 📥 **Каналы связи**: Telegram Bot API, Telegram (QR / пользовательский аккаунт через MTProto), WhatsApp (через whatsapp-web.js), Discord, Slack, VK (ВКонтакте через User Long Poll) и веб-формы (приём заявок с сайта). Модель расширяема.
- 🔔 **Вебхуки**: пересылка событий во внешние системы с подписью HMAC и повторными попытками.
- 💬 **История сообщений**: единая лента входящих и исходящих сообщений по всем каналам.
- 🔐 **Авторизация**: JWT, администратор по умолчанию, смена пароля.
- 🌐 **Мультиязычность**: русский, английский, испанский.
- 📊 **Дашборд**: сводная статистика.
- 📚 **Swagger**: документация API «из коробки».

## Быстрый старт (Docker Compose)

Требования: установленные Docker и Docker Compose.

```bash
# 1. Клонировать репозиторий
git clone https://github.com/KOSMOBOB/multichannel-hub.git
cd multichannel-hub

# 2. Создать файл окружения
cp .env.example .env
# при необходимости отредактируйте .env (пароли, секреты)

# 3. Запустить всё
docker compose up -d --build
```

После запуска:

| Сервис          | Адрес                                |
|-----------------|--------------------------------------|
| Админ-панель    | http://localhost:3000                |
| API             | http://localhost:4000/api            |
| Swagger         | http://localhost:4000/api/docs       |

**Учётные данные по умолчанию:** `admin@admin.com` / `admin123`
(смените пароль в разделе «Профиль» после входа).

## Конфигурация

Все настройки задаются через переменные окружения. См. `.env.example` в корне и в папках
`backend/`, `frontend/`.

| Переменная           | Описание                                       |
|----------------------|------------------------------------------------|
| `DATABASE_URL`       | Строка подключения к PostgreSQL                |

| `ADMIN_EMAIL/PASSWORD` | Учётные данные администратора по умолчанию    |

| `NEXT_PUBLIC_API_URL`| URL API для фронтенда                           |

## Подключение Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. В админ-панели: **Каналы → Добавить канал → тип Telegram**, вставьте токен.
3. Нажмите **«Установить вебхук Telegram»** и укажите публичный URL шлюза
   (Telegram должен иметь к нему доступ по HTTPS).
4. Сообщения боту начнут поступать в раздел **«Сообщения»**.

## Подключение WhatsApp

WhatsApp интеграция работает через **whatsapp-web.js** (неофициальный API, бесплатный, без токенов).
Требуется авторизация по QR-коду — как при подключении «Связанного устройства» в WhatsApp.

### Шаги подключения:

1. В админ-панели: **Каналы → Добавить канал → тип WhatsApp**, задайте имя канала.
2. После создания нажмите **«Инициализировать WhatsApp»** — запустится клиент.
3. Нажмите **«Получить QR-код»** — на экране появится QR-код.
4. Откройте WhatsApp на телефоне → **Настройки → Связанные устройства → Привязать устройство**.
5. Отсканируйте QR-код. После успешной авторизации статус изменится на **CONNECTED**.
6. Входящие сообщения из WhatsApp начнут поступать в раздел **«Сообщения»**.

### Отправка сообщений:

Используйте API-эндпоинт:
```bash
POST /api/whatsapp/channels/{channelId}/send
{
  "phoneNumber": "79001234567@c.us",
  "text": "Здравствуйте!"
}
```

> ⚠️ **Важно:** Сессия WhatsApp сохраняется в папке `whatsapp-sessions/` — при удалении контейнера
> авторизация сбросится. Для продакшена рекомендуется использовать volume для этой папки.

## Подключение Telegram (QR, пользовательский аккаунт)

Помимо Telegram **Bot API**, поддерживается подключение **обычного аккаунта Telegram** через
**MTProto** (библиотека [GramJS](https://github.com/gram-js/gramjs)). Авторизация выполняется
по QR-коду — как «Войти по QR» в официальном приложении. Сессия хранится и держится открытой,
ботом регистрироваться не нужно.

> Этот режим удобен, когда нужно отвечать клиентам от лица личного/рабочего аккаунта, а не бота.

### Что нужно заранее:

Каждый пользователь получает собственные **API ID** и **API Hash** (бесплатно):
1. Откройте [my.telegram.org](https://my.telegram.org) и войдите по номеру телефона.
2. Перейдите в **API development tools**, создайте приложение.
3. Скопируйте `api_id` и `api_hash` — они вводятся в настройках канала.

### Шаги подключения:

1. В админ-панели: **Каналы → Добавить канал → тип Telegram (QR)**, задайте имя канала.
2. Введите **API ID** и **API Hash**, сохраните канал.
3. Нажмите **«Инициализировать Telegram (QR)»**, затем **«Получить QR-код»**.
4. Откройте Telegram на телефоне → **Настройки → Устройства → Подключить устройство**.
5. Отсканируйте QR-код. Если включён облачный пароль (2FA) — система запросит его, введите пароль.
6. После авторизации статус изменится на **CONNECTED**, входящие сообщения начнут поступать в раздел **«Сообщения»**.

### Отправка сообщений:

```bash
POST /api/telegram-user/channels/{channelId}/send
{
  "peer": "@username",
  "text": "Здравствуйте!"
}
```

> ⚠️ **Важно:** Сессия сохраняется в БД (в `config.session` канала). Автоматизация пользовательского
> аккаунта формально противоречит ToS Telegram — избегайте массовых рассылок и спама, чтобы не получить бан.

## Подключение Discord

Discord интеграция работает через **discord.js** — официальную библиотеку для Discord Bot API.
Бот может получать и отправлять сообщения в каналы Discord-серверов (гильдий), к которым подключён.

### Что нужно заранее:

1. Перейдите на [Discord Developer Portal](https://discord.com/developers/applications).
2. Нажмите **New Application**, задайте имя бота.
3. В разделе **Bot** нажмите **Add Bot**, затем **Reset Token** и скопируйте **Bot Token**.
4. **Важно:** В разделе **Bot → Privileged Gateway Intents** включите:
   - **Message Content Intent** (чтобы бот мог читать текст сообщений).
5. В разделе **OAuth2 → URL Generator** выберите scope **bot**, permissions **Send Messages**, **Read Message History**, **View Channels**.
6. Скопируйте сгенерированный URL и откройте его — добавьте бота на свой сервер.

### Шаги подключения:

1. В админ-панели: **Каналы → Добавить канал → тип Discord**, вставьте **Bot Token**.
2. Нажмите **«Инициализировать Discord»** — бот подключится к Discord API.
3. Проверьте статус кнопкой **«Статус Discord»** — должен быть **CONNECTED**.
4. Входящие сообщения из каналов Discord начнут поступать в раздел **«Сообщения»**.

### Отправка сообщений:

Для отправки сообщения укажите **Discord Channel ID** (получите его в Discord: ПКМ на канале → Copy ID):

```bash
POST /api/discord/channels/{channelId}/send
{
  "discordChannelId": "123456789012345678",
  "text": "Здравствуйте!"
}
```

> 💡 **Подсказка:** Channel ID — это длинное число (например, `1234567890123456789`), которое можно скопировать
> в Discord при включённом Developer Mode (Настройки → Расширенные → Режим разработчика).

## Подключение Slack

Slack интеграция работает через **@slack/web-api** и **@slack/bolt** — официальные SDK от Slack.
Поддерживается два режима:
- **API-only** (только отправка сообщений) — требует только **Bot Token**.
- **Socket Mode** (получение входящих сообщений) — требует **Bot Token**, **Signing Secret** и **App Token**.

### Что нужно заранее:

1. Перейдите на [Slack API](https://api.slack.com/apps) и нажмите **Create New App → From scratch**.
2. Задайте имя приложения и выберите workspace.
3. В разделе **OAuth & Permissions → Bot Token Scopes** добавьте:
   - `chat:write` (отправка сообщений)
   - `channels:history` (чтение истории каналов)
   - `groups:history` (чтение истории приватных каналов)
   - `im:history` (чтение личных сообщений)
4. Нажмите **Install to Workspace**, подтвердите — скопируйте **Bot User OAuth Token** (начинается с `xoxb-`).
5. **(Опционально, для Socket Mode):**
   - В разделе **Socket Mode** включите Socket Mode.
   - Создайте **App-Level Token** (scope: `connections:write`) — скопируйте токен (начинается с `xapp-`).
   - В разделе **Basic Information** скопируйте **Signing Secret**.

### Шаги подключения:

1. В админ-панели: **Каналы → Добавить канал → тип Slack**.
2. Вставьте **Bot User OAuth Token** (обязательно).
3. **(Опционально)** Вставьте **Signing Secret** и **App-Level Token** для получения входящих сообщений.
4. Нажмите **«Инициализировать Slack»** — бот подключится к Slack API.
5. Проверьте статус кнопкой **«Статус Slack»**:
   - **CONNECTED_SOCKET_MODE** — полная поддержка (отправка + приём).
   - **CONNECTED_API_ONLY** — только отправка сообщений.
6. Пригласите бота в нужные каналы командой `/invite @ИмяБота`.

### Отправка сообщений:

Для отправки сообщения укажите **Slack Channel ID** (например, `C1234567890`) или имя канала (`#general`):

```bash
POST /api/slack/channels/{channelId}/send
{
  "slackChannelId": "C1234567890",
  "text": "Здравствуйте!"
}
```

> 💡 **Подсказка:** Channel ID можно найти в Slack: откройте канал → в адресной строке браузера последний сегмент
> после `/` — это Channel ID (например, `https://app.slack.com/client/T.../C1234567890`).

## Подключение VK (ВКонтакте)

VK интеграция работает через **vk-io** — библиотеку для работы с VK API и User Long Poll.
Используется **личный аккаунт** (не группа) для отправки и получения личных сообщений.

### Что нужно заранее:

1. Получите **Access Token** от личного аккаунта ВКонтакте:
   - Перейдите на [vk.com/dev](https://vk.com/dev).
   - Создайте **Standalone-приложение**.
   - В настройках приложения скопируйте **ID приложения**.
   - Получите токен через Implicit Flow или воспользуйтесь готовым сервисом генерации токенов (например, vkhost.github.io).
   - Токен должен иметь права: **messages** (доступ к сообщениям) и **offline** (бессрочный токен).
2. Токен выглядит примерно так: `vk1.a.AbCdEf1234567890...`

> ⚠️ **Важно:** Используйте токен личного аккаунта (User Token), а не токен сообщества (Group Token).
> User Token позволяет отправлять и получать личные сообщения от имени вашего аккаунта.

### Шаги подключения:

1. В админ-панели: **Каналы → Добавить канал → тип VK (ВКонтакте)**.
2. Вставьте **Access Token** вашего личного аккаунта.
3. Нажмите **«Инициализировать VK»** — система запустит User Long Poll для получения входящих сообщений.
4. Проверьте статус кнопкой **«Статус VK»**:
   - **CONNECTED** — бот подключён и получает входящие сообщения.
   - **DISCONNECTED** — бот отключён.

### Отправка сообщений:

Для отправки сообщения укажите **VK User ID** получателя (числовой ID пользователя):

```bash
POST /api/vk/channels/{channelId}/send
{
  "userId": 123456789,
  "text": "Привет из Multichannel Hub!"
}
```

> 💡 **Подсказка:** User ID можно узнать через профиль ВК или с помощью встроенных методов VK API.

### Получение входящих сообщений:

Входящие сообщения автоматически:
- Сохраняются в базу данных с меткой **INBOUND**.
- Отправляются на настроенные вебхуки с событием `message.received`.
- Отображаются в разделе **Сообщения** админ-панели.

## Приём заявок с веб-формы

1. Создайте канал типа **Web Form**, скопируйте его `ID`.
2. Отправляйте `POST` на `/api/webforms/{channelId}/submit` с полями формы.

См. подробности в [API.md](./API.md) и [INTEGRATION.md](./INTEGRATION.md).
